## The serial-port contention model (the through-line)

Four consumers all need **exclusive** access to the same `/dev/tty.usbmodem*` port:

| Consumer | Mechanism | Where |
|---|---|---|
| Interactive REPL | node-serialport `SerialPort` (`replPort`) | `electron/main.ts` |
| Run code | writes to existing `replPort` (paste mode) | `run-code` handler |
| Upload | spawns `mpremote cp` | `upload-code` handler |
| Device file tree | spawns `mpremote ls` (debounced 1.5 s) | `src/components/device-file-tree.tsx` |
| Flash | spawns `esptool` | `flash-firmware` handler |

Rule: before any non-REPL consumer touches the port, the REPL `replPort` must be closed
**and** the OS handle released, **and** no other consumer may grab it in the gap.

## Issues debugged & fixed this session

### 1. Run via REPL (paste mode) — DONE (prior session)
`Run` on a WiFi script gave `TransportError: could not enter raw repl` because the REPL
held the port. Fixed by running code *through* the existing REPL connection via paste mode
(`Ctrl-C Ctrl-C`, `Ctrl-E`, code, `Ctrl-D`) instead of spawning mpremote. `run-code`
handler returns `viaRepl: true`; renderer switches `bottomMode` to `repl`.

### 2. Flash downloaded `.uf2` as raw `.bin` — DONE (prior session)
`getMicroPythonUrl` grabbed the first firmware link (now a `.uf2` for S3). esptool needs a
raw `.bin`. Fixed to prefer `.bin` (exclude `.app-bin` OTA), `.uf2` only for RP2040.
**This was the original "silent REPL" root cause** — the board had been flashed a UF2 container as a raw image.

### 3. Flash reset mode for USB-Serial/JTAG — DONE (prior session)
Replaced single attempt with an attempts array:
`[{460800,default_reset},{115200,default_reset},{115200,no_reset}]` with recursive retry.

### 4. REPL converted to a real terminal — DONE (prior session)
New `src/components/repl-terminal.tsx` using xterm.js (`@xterm/xterm` 6.0.0,
`@xterm/addon-fit` 0.11.0). Raw keystrokes → device, device bytes → xterm, so the
MicroPython banner / ANSI / echo render correctly. `bottom-panel.tsx` renders
`<ReplTerminal />` when `replConnected`.

### 5. Flash modal auto-hide + main-process port release — DONE (prior session)
- `handleConfirmFlash` calls `setFlashDialogOpen(false)` after `setIsFlashing(true)` so the
  shell is watchable.
- `flash-firmware` handler closes `replPort` at the top of its try block (the authoritative
  place — renderer state can be stale).

### 6. Runtime profile not auto-selected after restart — DONE (this session)
Root cause: the store persists `selectedPort`/`lastPortPath` but **not**
`availableProfiles`/`activeProfile`. On a fresh launch the port is restored, so the
auto-connect reconnect path early-returned without re-running profile detection, and
`refreshPorts`' "current port" branch repopulated the profile *list* but never selected one.

Fixes:
- `src/lib/use-auto-connect.ts` — reconnect branch now repopulates profiles when
  `availableProfiles`/`activeProfile` are missing, not only when the port changes.
- `src/App.tsx` `refreshPorts` (current-port branch) — selects the saved/best profile when
  none is active.

### 7. Board identification — catalog + picker — DONE (this session) ⭐ feature
User wants friendly board names (M5Stack ATOM Lite, M5StampS3, Seeed XIAO ESP32S3 Sense).
**Hardware constraint:** every ESP32-S3 board on *native* USB presents the identical
descriptor (`303a:1001`) — M5StampS3 / XIAO / bare S3 are indistinguishable from USB alone.

- **New `src/lib/boards.ts`** — `BOARD_CATALOG` (single source of truth), `identifyBoard()`
  (override → descriptor match → chip-family fallback + candidate list), `getBoardById()`,
  `portKey()`. Each board carries `flashBoardType` (legacy `BoardType` for the flash handler)
  and `mpyVariant`. Distinguishable: ATOM Lite (`10c4:ea60`), M5StampS3 (`303a:80xx`),
  Pico (`2e8a`), Arduino (`2341`). Ambiguous S3 → "Generic ESP32-S3" + picker.
- **Store** (`src/lib/store.ts`): added `serialNumber?` to `PortInfo`; added persisted
  `boardOverrides: Record<string,string>` + `setBoardOverride(portKey, boardId)`.
- **UI** (`src/App.tsx`): friendly name in status bar + BOARD panel (falls back to legacy
  `BOARD_INFO` label while the port list loads); a **Board** picker appears for ambiguous
  ESP32-S3 boards (`candidates.length > 1`) and persists the choice per serial number;
  effect syncs `detectedBoard` (legacy `BoardType`) from the resolved board's `flashBoardType`
  so the picked board drives which firmware is flashed.
- `serialNumber` already flows through IPC (`SerialPort.list()` returns it) — no main change.

### 8. Upload `could not enter raw repl` — busy-board handoff — DONE (this session)
Board healthy, but `Run` left the WiFi script running (blocks in `wlan.connect()` / loop).
`withReplPaused` closed the port and handed it to mpremote **without interrupting** the
running program → mpremote can't enter raw REPL on a busy board → 10 s timeout.

Fixes in `electron/main.ts`:
- `withReplPaused` now writes `\r\x03\x03` (Ctrl-C ×2) through the live REPL, waits 200 ms to
  let the board settle at `>>>`, **then** closes (delay bumped 150 → 250 ms for native-USB
  re-enumeration).
- `upload-code` retries mpremote once after 600 ms if the error matches `/raw repl/i`.

### 9. Flash `port is busy` — device-tree race — DONE (this session) ← most recent
`handleConfirmFlash` sets `replConnected=false`; the device file tree watches that and
scheduled a debounced (1.5 s) `mpremote ls`, which fired **mid-flash** and stole the port
(esptool's `flash_id` *and* `write_flash` both failed to lock). The tree skipped refresh
while the REPL was connected but had **no `isFlashing` guard**.

Fixes in `src/components/device-file-tree.tsx`:
- `refreshDeviceFiles` early-returns when `isFlashing || isInstalling`.
- `isFlashing`/`isInstalling` added to the effect deps, so flipping `isFlashing` true
  **cancels the already-scheduled probe timer**.
- Manual refresh button disabled during flash/install.

## Known issues / pending

1. **Full test suite OOMs / worker-teardown hang (PRE-EXISTING, not from these changes).**
   `tests/unit/app-comprehensive.test.tsx` passes its tests but the vitest worker won't
   terminate (~891 s then force-kill) — an open handle keeps the event loop alive, almost
   certainly App's `setInterval(refreshPorts, 3000)`. Running the whole suite at once then
   OOMs (`--max-old-space-size` 8192 still dies). **Fix idea:** fake timers / assert interval
   cleanup, or `unref()` the interval, so CI can run the suite single-process. Flagged to the
   user as a spin-off cleanup task (not yet started).

2. **mpremote on ESP32-S3 native USB may still toggle DTR/RTS on open.** If upload still
   fails after #8, the next suspect is mpremote resetting the S3 on port open. The
   interrupt-before-handoff fixes the busy-board case (the observed symptom); DTR is the
   remaining theory if it recurs.

3. **Dev vs prod dependency policy (user constraint).** In dev, use system-level tools
   (`python3 -m esptool`, `mpremote`); in a production build, everything must be packaged
   inside the Electron bundle. Current flash/upload call system `python3 -m …` — the bundling
   path is NOT yet implemented.
