## TL;DR

The prior session closed the serial-port **contention** holes (REPL ↔ upload ↔ device-tree ↔ flash). This session built **on top of that**: the through-line is *never hand off the port* and *make Anode adapt to whichever board+runtime is connected, one at a time*. We:

1. Made **upload** go through the open REPL (raw-REPL) instead of an mpremote port handoff — kills the `could not enter raw repl` failure on a busy native-USB ESP32-S3.
2. Fixed **REPL connect** (needed multiple clicks; not interactive; output glued to the prompt).
3. Made the **runtime/workspace follow a board swap** and added **CircuitPython auto-detection + a CircuitPython drive provider** (third runtime now actually works end-to-end).
4. Added **no-BOOT-button flashing** (1200-baud touch for native-USB ESP; `machine.bootloader()` for RP2040).
5. Extracted testable helpers and added test coverage; ran a **competitive gap analysis** (roadmap below).

**Verified on hardware:** Seeed XIAO ESP32-S3 (flash → run → upload → REPL all working). **Needs hardware verification:** CircuitPython drive provider, 1200-touch no-button flash, RP2040 `machine.bootloader()`.

## What changed this session

### 1. Upload via raw-REPL (no port handoff) — `electron/main.ts`
- New `uploadViaRepl(fileName, code)` writes the file over the **already-open `replPort`** using the raw-REPL protocol: Ctrl-C ×2 → Ctrl-A → `import binascii` / `open(...,'wb')` / chunked `f.write(binascii.unhexlify(...))` (512-byte hex chunks, flow-controlled per round-trip) / `f.close()` → Ctrl-B.
- New `replCaptureBuf` hook in `attachReplHandlers`: while set, incoming bytes are diverted to a capture buffer (not forwarded to the renderer) so the raw-REPL protocol doesn't spam the terminal.
- `upload-code` now **prefers** `uploadViaRepl` when the REPL is connected; falls back to the old `withReplPaused` + mpremote handoff only when it isn't. (That fallback still has the DTR/RTS-reset risk on native USB — see Known issues.)

### 2. REPL connect reliability — `electron/main.ts`, `store.ts`, `bottom-panel.tsx`, `device-file-tree.tsx`
- `openReplPort` **retries the open up to 5×** (350 ms apart) on transient busy (device-tree probe / native-USB re-enumeration) → a single Connect click works.
- After open, it **nudges the prompt twice** (`\x03\x03\x02` at 350 ms, `\x03` at 1000 ms) to interrupt a board still booting → the `>>>` prompt appears and the terminal is interactive.
- Terminal newline fix: the REPL data handler now forwards verbatim when `filtered.length > 0` (was `filtered.trim()`), so bare `\r\n` chunks aren't dropped — fixes `print('hi')hi` (output glued to the command).
- New `replConnecting` store flag (set during `handleReplConnect`); the device file tree skips its `mpremote ls` probe while connecting (and cancels a scheduled probe), so it can't steal the port mid-connect.

### 3. Runtime follows the board; manual picks preserved — `App.tsx`, `store.ts`
- New pure `resolveProfileOnDetect({current, profiles, savedId, manual})` in the store decides the active profile on each detection: fresh-launch restore; **auto** profiles track the best detection (so a board swap or a mounting CIRCUITPY drive flips the runtime); **manual** picks are preserved unless the board genuinely swaps (id gone).
- New `profileManuallySet` flag: `selectProfile` sets it true (pin), `setActiveProfile` sets it false (auto).
- `refreshPorts` current-port branch uses `resolveProfileOnDetect` instead of the old `if (!activeProfile)` guard → fixes the stale-runtime-after-swap bug.

### 4. CircuitPython detection — `electron/main.ts`, `preload.ts`, `interpreter.ts`, `store.ts`, `App.tsx`, `use-auto-connect.ts`
- `detect-circuitpython` IPC scans OS mounts (macOS `/Volumes`, Linux `/media`,`/run/media`) for a `CIRCUITPY` volume and parses `boot_out.txt` (board name + CP version) via `parseBootOut`.
- `ProfileDetectionInput.circuitPython` hint → `detectExecutionProfiles` injects a **high-confidence CircuitPython profile first**, so it wins `selectBestProfile` even on a bare ESP32-S3. Added Adafruit VID `239a` signature for descriptor-level detection.
- `circuitPythonDrive` store state + `circuitPythonHint()` helper, fed into every `detectExecutionProfiles` call site (refreshPorts ×2, manual picker, both use-auto-connect paths). The probe runs each `refreshPorts` tick.

### 5. CircuitPython drive provider — `electron/main.ts`, `preload.ts`, `App.tsx`
- `circuitpython-deploy` IPC copies a file onto the mounted `CIRCUITPY` drive (re-validates `boot_out.txt`; `path.basename` guards traversal). CircuitPython auto-reloads on file write.
- `App.tsx` `deployToCircuitPython()` helper + `handleRun`/`handleUpload` branches on `workspaceMode === 'circuitpython'`: Run copies the current file (warns if not `code.py`/`main.py`), Upload copies all deployable files. Works without a selected serial port (drive is the target); REPL stays serial for output.

### 6. No-BOOT-button flashing — `electron/main.ts`, `electron/main/utils/flashing.ts`
- `bootloaderTouch1200(portPath)`: 1200-baud open + drop DTR/RTS + close (2.5 s safety guard). CircuitPython / recent MicroPython reboot themselves into the download bootloader.
- Espressif flash path: on **native USB** (`303a` / `usbmodem`) it now **skips the resetting `flash_id` probe** (uses the VID; esptool re-detects during `write_flash`), does the touch right before writing, and tries **`no_reset` first** (board already in download mode).
- `enterRp2040Bootloader(portPath)`: sends `machine.bootloader()` over serial so the Pico drops into the `RPI-RP2` UF2 drive; the `raspberry-pi` case polls up to 10 s for the drive, then copies the `.uf2`.

### 7. Testability refactor — `electron/main/utils/flashing.ts`, `store.ts`
Pure, dependency-free helpers extracted from the flash handler (`parseBootOut`, `needsManualReset`, `flashAttempts`, `rp2040MountPoints`, `chipTypeFromFlashId`, `chipTypeFromVid`, `flashOffset`, `isEsptoolConnectionError`) and the swap decision (`resolveProfileOnDetect`).

## Roadmap — competitive gap analysis (Thonny / Arduino IDE 2.x / Arduino Lab / Mu / PlatformIO / circup + CircuitPython web workflow / ViperIDE / ESP Web Tools / micro:bit)

**Anode already wins on:** only IDE spanning all three runtimes in one app; built-in firmware flashing (esptool + 1200-touch + UF2) better than Thonny/Mu/Arduino-Lab; best-in-class board detection (VID/PID + CIRCUITPY + boot_out + confirm-once picker); tool auto-detect/install.

**P0 — table-stakes still missing:**
1. **On-device library manager** (biggest gap) — wrap `circup` (CircuitPython, USB + WiFi), `mip`/mpremote (MicroPython), `arduino-cli lib` (Arduino) behind one "Add Library" search+install panel.
2. **Serial plotter** — parse CSV/newline serial into live multi-series graphs (reuse the existing stream). Canonical beginner "see your sensor" moment.
3. **Examples/templates gallery** — extend `src/lib/templates.ts` into a board-/runtime-aware browsable gallery (blink, WiFi, I2C sensor, display).
4. **Device-sourced REPL autocomplete** — tab-complete by querying `dir()` on the live device.
5. **REPL session auto-resume after device reset** — port-level reconnect exists (`use-auto-connect.ts` + this session's REPL connect-retry); the gap is the REPL showing "--- Disconnected ---" on a board reset instead of silently resuming. Closing this beats Thonny's "Device is busy" reputation.

**P1 — differentiators:** WebSerial **browser version** (Anode already uses esptool → esptool-js is the same engine in-browser); **CircuitPython Web Workflow** (WiFi REST file sync + WebSocket REPL + `circup --host`); hardware debugger (PlatformIO/Arduino-IDE have it).

**P2:** RTC clock sync on connect (Thonny does it); cloud sketch share; simulator; Ruff lint/format.

Full cited report (~20 sources) was produced by a research subagent this session.

## Known issues / pending

1. **Full test suite OOMs / worker won't terminate (PRE-EXISTING).** `app-comprehensive.test.tsx` keeps the vitest worker alive (~891 s then force-kill) — almost certainly App's `setInterval(refreshPorts, 3000)`. Fix idea: `unref()` the interval or fake timers so CI can run single-process. Run files individually for now.
2. **mpremote upload fallback still resets native USB.** When the REPL is *not* connected, `upload-code` falls back to mpremote (port handoff → DTR/RTS reset). Optional improvement: have the upload open a short-lived REPL connection itself so it always uses `uploadViaRepl`.
3. **1200-touch / RP2040 caveats.** Blank/bricked boards still need the one-time manual BOOT+RESET (nothing listening for the touch). If the board re-enumerates to a *different* `/dev/tty` path after the touch, esptool may miss it on the first try.
4. **Windows CIRCUITPY/RPI-RP2 detection** is mac/Linux only (volume-label enumeration TODO). CircuitPython still detects via the `239a` VID on Windows.
5. **Dev vs prod dependency bundling NOT implemented.** Flash/upload call system `python3 -m esptool` / `mpremote` / `arduino-cli`. `electron/main/utils/paths.ts` has the `getBundledBinPath`/`extraResources` scaffolding but it isn't wired into the spawn calls yet. Production needs per-OS bundled, code-signed binaries.

## Vision (user)
Anode = the go-to desktop (and later web) IDE for SBC/microcontroller programming, beginners → experts. One board at a time, but seamless switching between boards **and** runtimes (Arduino on one, CircuitPython on the next, MicroPython on another). This session made that switching real (runtime follows the board) and added the CircuitPython runtime end-to-end.
